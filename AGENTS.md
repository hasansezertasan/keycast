# keycast

Keycast is a cross-platform keystroke and mouse click visualizer built in Python.

## Rules

### package-structure

**Priority:** high

Flat modules under `src/keycast/`, plus one `updates/` subpackage. There is no
`core/` / `utils/` / `cli/` / `gui/` package tree, and no import-linter contract
(the layout predates the template's layered convention).

| Module | Role |
| ------ | ---- |
| `application.py` | `Keycast` composition root — the ONLY place that wires components (settings → logging → window → listeners) |
| `main.py`, `cli.py`, `__main__.py` | Thin entry points. `keycast.cli:app` is the console script; `python -m keycast` runs `main()` |
| `listeners.py` | `KeyListener` / `MouseListener`: pynput threads format each event into one display string and push it to a `TextSink` (`Callable[[str], None]`). They know nothing about the display |
| `display.py` | `DisplayWindow`: the Tk overlay, the production sink (`show_text` marshals onto the Tk loop via `root.after`) |
| `settings.py` | Pydantic settings loaded from JSON ONLY (`~/.keycast/config.json`) — constructor kwargs and env vars are ignored. Never `Settings(display=...)`; patch the JSON source in tests |
| `logging_setup.py` | Rotating-file logging setup (defaults to `~/.keycast/main.log`) |
| `secure_input.py` | macOS secure-input masking probe (best-effort, macOS-only) |
| `updates/` | Install-source-aware update check (notify only): `sources` (how installed), `versions` (GitHub fetch + compare), `state` (once-a-day throttle), `__init__` orchestration |

Design rules that must survive every change:

- **Single-sink event flow.** Mouse position is formatted *into* the string so the
  sink signature stays uniform; tests pass `list.append` as the sink.
- **Threading & shutdown are subtle.** Listeners run on pynput threads; the fade
  timer is a self-rescheduling `root.after(100, ...)` (no separate thread).
  Shutdown is two-phase: `request_stop()` (any thread) schedules `root.quit`;
  `stop()` runs on the main thread after `mainloop` returns and destroys the
  window. Never destroy the window from inside `mainloop` (Tcl errors).
- **Degrade, don't crash.** Input-capture code catches broadly by design
  (`except Exception` + multi-statement `try` blocks are the error policy, see
  the `BLE001`/`PLW0717` per-file-ignores in `pyproject.toml`); a listener
  failure must never take down the overlay. Narrow a handler only when you can
  prove the failure set.
- **Lazy imports are load-bearing.** `tkinter` stays function-local
  (`PLC0415`), and the `cli.py` subcommands import the GUI chain lazily, so
  `--help`, `version`, and `info` never pay for the GUI toolkit. `pynput` is
  the exception, not the rule: `listeners.py` imports it at module scope, so
  anything importing the listener chain (tests, Sphinx autodoc, a bare
  `python -m keycast`) needs a display — CI and the dev container provide
  Xvfb for exactly this. Sphinx autodoc is the other exception: the three
  names it renders (`types`, `DisplaySettings`, `LoggingSettings`) are runtime
  imports with `noqa: TC001/TC003` — moving them back under `TYPE_CHECKING`
  breaks the docs build.

### project-conventions

**Priority:** high

- Source lives in `src/keycast/`; tests mirror it under `tests/`.
- `src/keycast/_version.py` is generated by hatch-vcs — never edit it.
- Absolute imports only; strict typing; Python 3.14 only (`requires-python >= 3.14`,
  single 3.14 tox env — the template's 3.10–3.13 sweep does not apply).
- Max cyclomatic complexity 5 (ruff-enforced); input-handler complexity is
  documented per site with `# noqa: C901` — refactor those only with care.
- Versions come from Git tags — do not hand-edit a version literal anywhere.
- Commit messages follow Conventional Commits; releases are automated by release-please.
- **Docs are a contract.** `README.md` and `docs/` (API, ARCHITECTURE,
  DESIGN_DECISIONS, PROJECT_OVERVIEW) must match the code; `tests/test_docs_contract.py`
  pins class/constructor names, the `Settings` section set, default key labels,
  and logging defaults. A failure means a doc claim and the code diverged — fix
  the mismatch, not the test.
- **Settings load from JSON only.** `Settings.create_settings_file()` is the load
  entry point: first run writes defaults atomically (tempfile + `os.replace`); a
  corrupt file is moved aside to `config.json.<epoch>.bak`; failures degrade to
  in-memory defaults. Settings load *before* logging, so recovery warns via
  stderr, not the logger.
- **Cross-platform key labels.** pynput names modifiers inconsistently across
  OSes; `_default_key_mappings` + `_super_key_labels` normalize per platform
  (Super → "Command"/"Windows"/"Super"). Users override via `key_mappings`.
- pyrefly prunes platform-guarded bodies (`if sys.platform != "darwin": return`)
  as dead code on non-darwin targets — widen the guard to a plainly-typed local
  (`host_platform: str = sys.platform`) where a macOS/Windows-only body must stay
  analyzable everywhere.
- `conf.py` carries project-added `exclude_patterns` (legacy `.md` docs stay
  GitHub-only); re-apply them after every `copier update`, which resets that file.

### pull-requests

**Priority:** high

CI blocks a PR whose branch name or title breaks these conventions — follow them
before opening one:

- **Branch names** follow [Conventional Branch](https://conventionalbranch.org/):
  `<type>/<short-description>` (e.g. `feat/add-login`). Allowed types are
  `feature`/`feat`, `bugfix`/`fix`, `hotfix`, `release`, `chore`, plus the
  AI-agent prefixes `ai`, `copilot`, `cursor`, `claude`, `codex`. The description
  is lowercase alphanumerics separated by single `-` or `.` (no leading, trailing,
  or consecutive separators). Enforced by `check-branch-name.yml`, which also
  whitelists the `renovate/*` and `release-please--*` automation branches — leave
  those as-is.
- **PR titles** follow [Conventional Commits](https://www.conventionalcommits.org/)
  (e.g. `feat: add login`) — the title becomes the squash commit release-please
  parses, so it drives versioning. Enforced by `check-pr-title.yml`.
- Every human-authored PR must **link an issue** (a `Closes #N` keyword in the
  body) unless it carries the `no-issue` label. Enforced by
  `check-linked-issues.yml`, which auto-skips PRs opened by a bot account (login
  ending in `[bot]`) — don't fabricate an issue reference for those.
