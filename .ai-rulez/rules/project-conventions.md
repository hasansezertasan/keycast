# Key conventions

- Source lives in `src/keycast/`; tests mirror it under `tests/`.
- `src/keycast/_version.py` is generated by hatch-vcs — never edit it.
- Absolute imports only; strict typing; Python 3.14 only (`requires-python >= 3.14`,
  single 3.14 tox env — the template's 3.10–3.13 sweep does not apply).
- Max cyclomatic complexity 5 (ruff-enforced); input-handler complexity is
  documented per site with `# noqa: C901` — refactor those only with care.
- Versions come from Git tags — do not hand-edit a version literal anywhere.
- Commit messages follow Conventional Commits; releases are automated by release-please.
  Do not add an AI `Co-Authored-By` trailer to commits.
- **Docs are a contract.** `README.md` and `docs/` (API, ARCHITECTURE,
  DESIGN_DECISIONS, PROJECT_OVERVIEW) must match the code; `tests/test_docs_contract.py`
  pins class/constructor names, the `Settings` section set, default key labels,
  and logging defaults. A failure means a doc claim and the code diverged — fix
  the mismatch, not the test.
- **Settings load from JSON only.** `Settings.create_settings_file()` is the load
  entry point: first run writes defaults atomically (tempfile + `os.replace`); a
  corrupt file is moved aside to `config.json.<epoch>.bak`; failures degrade to
  in-memory defaults. Settings load *before* logging, so recovery warns via
  stderr, not the logger.
- **Cross-platform key labels.** pynput names modifiers inconsistently across
  OSes; `_default_key_mappings` + `_super_key_labels` normalize per platform
  (Super → "Command"/"Windows"/"Super"). Users override via `key_mappings`.
- pyrefly prunes platform-guarded bodies (`if sys.platform != "darwin": return`)
  as dead code on non-darwin targets — widen the guard to a plainly-typed local
  (`host_platform: str = sys.platform`) where a macOS/Windows-only body must stay
  analyzable everywhere.
- `conf.py` carries project-added `exclude_patterns` (legacy `.md` docs stay
  GitHub-only); re-apply them after every `copier update`, which resets that file.
